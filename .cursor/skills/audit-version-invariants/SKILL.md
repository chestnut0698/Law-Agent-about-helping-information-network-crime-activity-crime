# 审计、权限与版本不变量

## 权限模型

每次服务端操作按四维检查：

1. 组织；
2. 用户角色；
3. 案件成员关系；
4. 具体操作权限。

跨组织和跨案件默认拒绝。

以下权限分别控制：

- 查看原始材料；
- 查看脱敏映射；
- 批准外部模型调用；
- 修改事实；
- 处理关键冲突；
- 启动量刑；
- 导出正式报告；
- 管理法律规则；
- 查看审计。

界面隐藏按钮不能代替服务端校验。

## 追加版本策略

不得原地覆盖：

- 文档替换；
- 事实和实体修正；
- 人工复核结果；
- 法律规则；
- Plan；
- 量刑计算；
- 报告。

使用：

- 递增 `version`；
- `supersedes_*` 链；
- 输入快照哈希；
- 创建人和时间；
- 关联人工复核或运行记录。

用户取消操作不得产生业务数据变更。

## 乐观锁

修改命令包含 `expected_version`。

版本不一致时：

1. 拒绝写入；
2. 返回最新版本；
3. 展示前后差异；
4. 要求用户重新确认；
5. 记录冲突事件。

## 人工复核

`human_reviews` 至少保存：

- 目标类型和 ID；
- `CONFIRM/CORRECT/EXCLUDE/DEFER/REOPEN`；
- 修改前后值；
- 修改理由；
- 复核人和时间；
- 影响分析 ID。

修正、排除和重新开启必须有理由。

“暂不判断”不等于确认，也不等于否定。

## 必须审计的事件

- 登录成功/失败、权限拒绝、角色变更；
- 案件创建、归档、重开；
- 文件上传、替换、删除、下载；
- 脱敏修改和外呼批准；
- Plan 生成、确认、暂停、恢复、重规划、取消；
- 每次模型和确定性工具调用；
- 人工确认、修正、排除和暂不判断；
- 规则草稿、复核、发布和停用；
- 量刑情景和计算；
- 类案采用状态；
- 报告生成、正式导出和日志导出。

审计只追加，普通用户不能修改或删除。

## 审计字段

至少包括：

- 操作者；
- 组织和案件；
- 事件类型；
- 目标类型和 ID；
- 前后值哈希；
- 理由；
- 请求 ID；
- IP 和设备；
- 结果；
- 时间。

敏感原始值不得写入普通审计正文；需要证明变化时保存哈希或受控加密引用。

## 归档和删除

- 案件归档为逻辑删除，只读。
- 重开需承办检察官权限并审计。
- 文档删除先执行影响分析。
- 数据销毁按留存策略覆盖正文、索引和缓存。
- 销毁后保留不含敏感正文的合规审计摘要。

## 正式报告版本

正式报告至少绑定：

- 案件数据版本；
- Plan 版本；
- 规则版本集合；
- 模型/Prompt 版本；
- 校核状态；
- 文件哈希；
- 导出人；
- 水印编号；
- 生成时间。

重复导出创建新版本，不覆盖旧文件。

## 事务规则

以下操作必须单事务：

- 业务写入 + 审计；
- 人工修正新版本 + 旧版本链接 + 复核记录；
- 脱敏映射 + 脱敏状态；
- 成果失效 + 新 Plan 创建；
- 报告元数据 + 文件哈希。

任何一步失败都必须回滚，不允许出现“数据已改但无审计”。

## 验收清单

- [ ] 非成员访问被服务端拒绝并审计
- [ ] 归档后只读
- [ ] 修正保留历史
- [ ] 取消修改无业务写入
- [ ] 乐观锁冲突可见
- [ ] 写操作和审计同事务
- [ ] 敏感值不进普通日志
- [ ] 文档替换使脱敏批准失效
- [ ] 过期成果不能正式导出
- [ ] 报告重复导出版本递增
- [ ] 审计可回答谁、何时、基于何版本、改了什么、为何修改
