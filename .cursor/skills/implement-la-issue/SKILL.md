# 信证智析 Issue 实施

## 开始前

1. 读取仓库根目录 `信证智析_智能体搭建实施规划.md` 的目标 Issue 全文。
2. 读取 `信证智析_PRD.md` 中同 ID Issue 和相关产品章节。
3. 检查目标 Issue 的前置依赖是否在代码、迁移和测试中真实存在。
4. 若依赖缺失，停止实现并报告具体缺失；不得绕过依赖或用 Stub 声称完成。
5. 按实施规划加载相关项目 Skill：
   - Plan/REPLAN：`plan-orchestration`
   - 事实、证据、实体：`fact-evidence-contract`
   - 法律输出和外呼：`legal-ai-safety`
   - 模型调用：`agent-role-model`
   - 写操作、权限、版本：`audit-version-invariants`

## 实施原则

- 一个 Issue 必须形成用户入口、服务逻辑、持久化、权限、审计和测试的纵向闭环。
- 页面只调用服务层，不得直接操作 ORM 或模型网关。
- 公共基础设施放在首个使用它的 Issue，不另建无法业务验收的横向 Issue。
- 不实现后续 Issue 的功能；仅为后续保留明确接口。
- 不将 Mock、占位页或固定假数据表述为正式能力。
- 外部依赖可提供测试适配器，但正式路径和测试路径必须明确隔离。
- 金额使用 Decimal；所有枚举、Schema 和数据库状态保持一致。

## 每次修改前输出实施清单

```text
目标 Issue：
前置依赖：
准备修改的文件：
新增迁移：
新增/修改契约：
页面交互：
审计事件：
测试文件：
明确不做：
```

## 默认完成定义

- [ ] 目标用户旅程可实际操作
- [ ] 服务端权限校验存在
- [ ] 关键写操作记录 audit_events
- [ ] Alembic 可从空库升级
- [ ] Pydantic 契约覆盖边界输入
- [ ] 异常信息包含原因、影响、下一步和错误编号
- [ ] 单元、集成和 E2E 通过
- [ ] 复用统一合成案卷
- [ ] 模型输出有 Schema 和原文校验
- [ ] 未引入定罪、证明标准或最终量刑能力
- [ ] `ruff check src tests` 通过

## 验收流程

1. 运行目标 Issue 在实施规划中指定的命令。
2. 运行全部已完成 Issue 回归测试。
3. 逐条复制目标 Issue 验收标准并标记：
   - `通过`：附测试名、页面路径或数据记录；
   - `未通过`：说明实际结果；
   - `未执行`：说明原因。
4. 检查前序 Issue 功能没有回归。
5. 写一份 `LA-XXX 完成记录`，使用实施规划第 31 节模板。

## 禁止行为

- 依赖未完成却将 Issue 标记完成；
- 只建表、只做 UI 或只写 Prompt；
- 用 UI 隐藏按钮代替服务端权限；
- 模型输出未经校验直接入业务表；
- 覆盖历史版本；
- 删除测试以通过验收；
- 擅自更改 PRD 责任边界；
- 将合成材料包装成真实案件。
