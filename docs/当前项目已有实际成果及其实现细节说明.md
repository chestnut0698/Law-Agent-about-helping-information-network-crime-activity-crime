# 链证智析

 目前项目名称为：

“链证智析”——面向基层检察院的帮信罪关联案件证据链条挖掘与漏犯漏罪智能监督系统

## 需求

处理串联不同案件卷宗里的证据，发现共同点，发掘上下游犯罪链条，辅助发现遗漏线索。或者能够从大量证据，如涉及大量言词证据、鉴定意见、电子数据等多种证据（诈骗罪、强奸罪、故意伤害罪等）中提取事实和证据要素，重在**发挥大语言模型的语义理解能力**。

## 项目实现

**智能体 = 大语言模型 + 提示词 + 数据库 + 工具**

## 技术栈

后端语言/运行时：Python 3.x（代码面向 3.11+），前端为静态 HTML/JS。

Web 框架：FastAPI + uvicorn（SSE 流式响应）。

模型/LLM调用：openai 客户端。

数据持久化：SQLite（sqlite3），

文档处理/OCR：PyMuPDF(fitz)、python-docx、Pillow；图片与扫描件默认由 DeepSeek 多模态转录文字，PaddleOCR 为可选离线兜底。

脱敏/NLP：presidio_analyzer + spaCy (zh_core_web_trf)、正则匹配。

其它辅助库：python-dotenv、pydantic、requests、baidusearch、prikit、pytest。

## 注意事项

脱敏不完全准确，可能需要人工复核

### 已有

默认接入 DeepSeek 的 `deepseek-flash`（读取 `DEEPSEEK_API_KEY`）。PNG/JPG/JPEG 与文字层过稀的 PDF 页在解析时把页面图交给该模型做文字转录，写入原有分块、脱敏与 `quote_hash` 回链；模型不直接对原图做跨案结论。无密钥或关闭外呼时再尝试本机 PaddleOCR。材料中心「纳入分析」只看解析状态是否为 `PARSED`，与案件授权不是同一件事；识字引擎升级后，已入库图片会按 `parser_version` 自动重解析，不再沿用从 PNG 二进制抠出的乱码。

当前对话按监督任务绑定：`/chat/{task_id}` 将消息写入 SQLite `chat_messages`。工作台主分析走智能体对话（DeepSeek ReAct + 任务工具）；快捷按钮走 `POST /api/tasks/{task_id}/collision/run`、`/timeline/run`。关联线索仅通过对话写入线索中心；规则命中、外号跨案、某一案共同参与人用 `list_association_hints` 作提示，不直接落库。人名抽取会裁掉称呼后误吞的动词，同姓外号与「X某」进入实体复核疑似队列（不自动合并）。会话附件兼容路径仍可用工作区目录；正式卷宗必须走材料管线。ReAct 智能体会调用模型；按项目提示词，智能体会自主调用工具完成对案件的分析。

界面为三栏原生工作台：左侧对齐参考前端的分析工作流导航（分析任务 / 材料中心 / 实体复核 / 线索中心 / 角色时间线 / 链条图谱 / 报告与审计）；中间为对应业务页（材料表、实体/线索 master-detail、对象关系图谱、报告）；右侧保留原智能体对话框。配色沿用现有 lime/灰主题。无任务时中间为新建任务页，创建成功后进入「分析任务」。人工判断在实体/线索页完成；核验完成后原判断按钮处保留「修改」，可改判「确认关联 / 保留独立」或线索处置，结论覆盖写入并追加核验留痕；核验留痕写入 `SOURCE_VERIFY`；《跨案关联线索核验单》由右侧智能体经报告读写工具撰写——先读取任务范围/实体复核结论/存活线索/既有草稿，再提交整篇正文，系统套固定边界与自动核对清单，报告为单份持续迭代（`REPORT_DRAFT` 升版本，不再走固定拼装接口）；下载时按当前版本即时转 docx（`GET /api/tasks/{id}/report.docx`），服务端只存储与管理 markdown。智能体侧按「计划 → 分步折叠（思考+执行）→ 展开回复」展示。API、产物类型保持不变。

链条图谱默认按「跨案桥」而不是时间线缩略图：节点为案件与跨案共同对象（人员/账户/电话/设备/组织等），`KEEP_SEPARATE` 的跨案候选作为已排除同一的断点虚线，不当作两案通路。对象之间仅在同一条时间线记载里共现时连「同事件记载」，边带原文回链。行为节点与「随后」默认不上图，可由「叠加行为」打开。侧栏展示跨案桥、同事件共现、通往其他案件的 2 跳实线路径与断点；线索只作跳转。无跨案共同对象时说明去时间线看单案行为，不把单案事件铺满。不把中心度解释为涉罪。
