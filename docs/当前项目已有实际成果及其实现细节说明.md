# 链证智析

 目前项目名称为：

“链证智析”——面向基层检察院的帮信罪关联案件证据链条挖掘与漏犯漏罪智能监督系统

## 需求

处理串联不同案件卷宗里的证据，发现共同点，发掘上下游犯罪链条，辅助发现遗漏线索。或者能够从大量证据，如涉及大量言词证据、鉴定意见、电子数据等多种证据（诈骗罪、强奸罪、故意伤害罪等）中提取事实和证据要素，重在**发挥大语言模型的语义理解能力**。

## 项目实现

**智能体 = 大语言模型 + 提示词 + 数据库 + 工具**

## 技术栈

后端语言/运行时：Python 3.x（代码面向 3.11+），前端为静态 HTML/JS。

Web 框架：FastAPI + uvicorn（SSE 流式响应）。

模型/LLM调用：openai 客户端。

数据持久化：SQLite（sqlite3），

文档处理/OCR：PyMuPDF(fitz)、python-docx、Pillow；图片与扫描件默认由 DeepSeek 多模态转录文字，PaddleOCR 为可选离线兜底。

脱敏/NLP：presidio_analyzer + spaCy (zh_core_web_trf)、正则匹配。

其它辅助库：python-dotenv、pydantic、requests、baidusearch、prikit、pytest。

## 注意事项

脱敏不完全准确，可能需要人工复核

### 已有

默认接入 DeepSeek 的 `deepseek-flash`（读取 `DEEPSEEK_API_KEY`）。PNG/JPG/JPEG 与文字层过稀的 PDF 页在解析时把页面图交给该模型做文字转录，写入原有分块、脱敏与 `quote_hash` 回链；模型不直接对原图做跨案结论。无密钥或关闭外呼时再尝试本机 PaddleOCR。材料中心「纳入分析」只看解析状态是否为 `PARSED`，与案件授权不是同一件事；识字引擎升级后，已入库图片会按 `parser_version` 自动重解析，不再沿用从 PNG 二进制抠出的乱码。

当前对话按监督任务绑定：`/chat/{task_id}` 将消息写入 SQLite `chat_messages`。工作台主分析走智能体对话（DeepSeek ReAct + 任务工具）；快捷按钮走 `POST /api/tasks/{task_id}/collision/run`、`/timeline/run`。跨案比对由规则做卡号/手机号等**等值碰撞**；不同称呼共用证卡号、外号、商户名、证件人像等「是否同一对象」由助手查阅材料后写入实体待核（`put_task_entity_candidate`），人工点视为同一/保留独立。关联线索仍由对话写入线索中心；规则命中用 `list_association_hints` 作提示。人名抽取会裁掉称呼后误吞的动词；「某」后一字若与后文构成谓语则留在谓语侧。指示代词加量词加物品通名不进人员映射。姓前称呼（老/小+单姓）按真姓出化名；同姓化名用天干序次（甲乙丙丁…），不用地支、不用下划线编号。材料中心提供「本任务脱敏映射」统一改映射，单份材料仍可打开对照原文。会话附件兼容路径仍可用工作区目录；正式卷宗必须走材料管线。ReAct 智能体会调用模型；按项目提示词，智能体会自主调用工具完成对案件的分析。

界面为三栏原生工作台：左侧对齐参考前端的分析工作流导航（分析任务 / 材料中心 / 实体复核 / 角色时间线 / 线索中心 / 链条图谱 / 报告与审计）；中间为对应业务页（材料表、实体/线索 master-detail、对象关系图谱、报告）；右侧保留原智能体对话框。配色沿用现有 lime/灰主题。无任务时中间为新建任务页，创建成功后进入「分析任务」。实体复核分标识队与人物队；字段对照只读。人工判断在实体/线索页完成：实体「视为同一 / 保留独立」只结束该张对象卡本身；线索是否已确认关联只认线索中心处置，不因实体复核完成、同名/外号共现或标识同一性方面而整批标绿。核验完成后原判断按钮处保留「修改」，可改判「确认关联 / 保留独立」或线索处置，结论覆盖写入并追加核验留痕；核验留痕写入 `SOURCE_VERIFY`（实体决策、线索处置、报告撰写与导出）。《跨案关联线索核验单》由右侧智能体经报告读写工具撰写正文，系统套固定边界并生成核对清单——清单为事实源，含分析范围、实体视为同一/保留独立脱敏名单、待核线索及连续来源编号（案名·文件·页·短摘录），并附图谱/时间线导航与未处置线索条数。每次撰写新增一版 `REPORT_DRAFT`（新写为 `report-{n}`；旧的同一 `report-draft` 多版本会按历史拆成多行），不覆盖旧版；列表一行一版，标签为「有效版本 / 存在失效引用 / 已下载 X 次」。下载指定报告即时转 docx（`GET /api/tasks/{id}/report.docx?report_id=&version=`），只记次数，不另开新版；docx 与页内预览均按公文常用项：A4，上 37mm / 下 35mm / 左 28mm / 右 26mm，文题黑体二号居中，节题黑体三号，小节楷体三号，正文仿宋三号、首行缩进两字、固定行距 28 磅。智能体侧思考过程用「>」折叠，点开后同一符号右转朝下；只展示法律人能看懂的中文核验说明，不展示模型英文思维链、参数、JSON 或技术明细。最终回复下方按本轮动作附带跳转按钮（实体复核 / 时间线 / 线索中心等）。停在实体复核时右侧会定时检测待核条数，全部「视为同一 / 保留独立」后自动续跑时间线与线索；线索写入后同样停等，线索中心全部处置完毕再自动撰写核验单，可取消自动继续。时间线在线索之前：用实体归并主体，供资金/时空线索对照；线索确认只进入报告路径合成，不回头改时间线抽取。撰写报告前若仍有未处置线索会被门禁拦住。左栏材料中心 / 实体复核 / 线索中心的绿色角标为待确认条数（材料需关注、对象待判断、线索未处置）。实体/线索/时间线/图谱/材料中心里打开原文，与材料中心正文预览同一套按文书层级排版的预览；管道表允许行间空行、可无分隔行，渲成带框线的 HTML 表格并可横向滚动。回链高亮先在未预览原文上按可见字定位并插入标记，再渲染预览，避免标题/表格符号导致黄底错位滑动。界面文案面向检察官，不展示 Markdown、存储路径、案件库等工程用语。API、产物类型保持不变。

链条图谱默认按「跨案桥」而不是时间线缩略图：节点为案件与跨案共同对象（人员/账户/电话/设备/组织等）。跨案边名区分「跨案出现（已确认同一）」（实线）与「跨案出现（待核）」（虚线）。`KEEP_SEPARATE` 的跨案对象不连线，不当通路，名单放在侧栏，点名称可回实体复核。对象之间仅在同一条时间线记载里共现时连「同事件记载」，边带原文回链。行为节点与「随后」默认不上图，可由「叠加行为」打开。侧栏展示跨案桥、同事件共现、通往其他案件的 2 跳实线路径与已排除同一名单；线索只作跳转。无跨案共同对象时说明去时间线看单案行为，不把单案事件铺满。不把中心度解释为涉罪。
