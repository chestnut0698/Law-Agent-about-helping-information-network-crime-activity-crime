# 链证智析

 目前项目名称为：

“链证智析”——面向基层检察院的帮信罪关联案件证据链条挖掘与漏犯漏罪智能监督系统

## 需求

当前需求：处理串联不同案件卷宗里的证据，发现共同点，发掘上下游犯罪链条，辅助发现遗漏线索。或者能够从大量证据，如涉及大量言词证据、鉴定意见、电子数据等多种证据（诈骗罪、强奸罪、故意伤害罪等）中提取事实和证据要素，重在**发挥大语言模型的语义理解能力**。这一部分需求的实现重在流程设计以及工具快速检索能力（RAG）。

## 项目实现

当前流程暂时设计的实现方式：按照流程步数执行，每一步以大模型返回文字为结束，因为当前只需要最后一次的文字输出，所以系统提示词会要求每一步大模型都返回空语句标志结束，直到最后一步生成完整回答。

这个流程具体还是要修改的，具体可以让cursor参照需求修改优化，尽可能的让大语言模型不受束缚的发挥出最大潜力。

### 已有（会话原型）

当前对话按监督任务绑定：`/chat/{task_id}` 将消息写入 SQLite `chat_messages`（不再用 `conversations.json` 目录存会话）。工作台主分析走 `POST /api/tasks/{task_id}/agent/chat`（DeepSeek ReAct + 任务工具）。会话附件兼容路径仍可用工作区目录；正式卷宗必须走材料管线。遗留 ReAct 与任务智能体均经 `agents/gateway.py` 调模型；`read_any_file` / `list_user_files` 标明未经脱敏门控，不得用于抽取或碰撞。

默认接入 DeepSeek 的 `deepseek-v4-flash`（读取 `DEEPSEEK_API_KEY`）。若本地未配置 DeepSeek、只配置了 `NVIDIA_API_KEY`，则自动走 NVIDIA，方便队友本地使用。NVIDIA 手动探针保留在 `test/test.py`。所有业务侧模型调用的唯一出口是网关；`test/test.py` 作为队友本地探针可直连，不计入业务旁路。

### 阶段三已落地：案件材料管线（智能体侧）

- **案件级导入 API**：`POST /api/materials/upload` 支持同一请求多文件、按 `case_id` 归属；格式 PDF / PNG / JPEG / DOCX / TXT。
- **版本链**：`documents` + `document_versions`；替换与 OCR 人工修正均新增版本，不覆盖历史；同案同 SHA-256 进入 `DUPLICATE_PENDING`；删除为逻辑删除并返回影响清单。
- **解析 / OCR / 分块**：PyMuPDF 页级取文；低密度页与图片走页级 OCR（已装 PaddleOCR 则用之，否则 Fallback 引擎便于本地/测试）；chunk 稳定键 `document_version_id + ordinal + sha256`（默认 800/120）。
- **状态与质量**：`PARSED` / `NEEDS_OCR_REVIEW` / `OCR_FAILED` / `FAILED` 等；页级置信度与质量标记可查询。
- **脱敏与外发门控**：本地检出姓名/身份证/银行卡/手机/IMEI/IP/住址/账号；对照映射隔离存放；Agent 仅能读脱敏 chunk，未脱敏拒绝外发。
- **授权**：仅实现授权检查契约（`auth_check(user_id, case_id, action)`）。未设置 `MATERIAL_AUTH_MODE` 时，`APP_ENV=development` 默认 `allow_all`；生产应显式 `deny_all`。本地演示也可在 `.env` 写 `MATERIAL_AUTH_MODE=allow_all`。**完整登录/RBAC 未实现。**
- **Agent 工具**：`list_case_materials`、`get_material_status`、`locate_low_quality_pages`、`read_material_chunk`、`submit_ocr_correction`。

### 工作台第一刀已落地：监督分析任务壳 + 材料进度

沿用 FastAPI + `ui/` 原生前端，不换框架。产品对象是“监督分析任务”，底层可复用 conversation id 承载智能体会话。

- **后端** `tools/tasks.py`：任务范围、计划确认、产物写入与版本追加、影响预览与 STALE 标记；复用 `files.py` 的数据库访问与材料服务。
- **接口**（均在 `app/main.py`）：`/api/tasks`、`/api/tasks/{id}/plan`、`/plan/confirm`、`/materials`、`/artifacts/{id}`、`/impact`。
- **前端**：四区壳（常驻全局任务栏 / 常驻任务目录 / 中间产物标签 / 可收起智能体）；新建任务先填范围再确认计划；材料批次产物展示逐文件处理进度；目录与智能体产物卡片共用 `artifact_id`。
- **视觉**：浅色 / 深色双主题，强调色 `#85CC16`；浅色面板 `#F4F4F6` / `#F6FEE7`，深色面板 `#17191B`、底色 `#0E1011`，样式在 `ui/styles/workbench.css`。
- **主题切换**：全局栏底部按钮切换并写入 `localStorage`；未手动选择过时跟随系统 `prefers-color-scheme`，`index.html` 内联脚本在样式生效前定妥 `data-theme`，避免首帧闪白。深色下同时设置 `color-scheme: dark`，日期选择器、滚动条等原生控件一并变深。
- **本地演示**：未设置 `MATERIAL_AUTH_MODE` 时，开发环境默认允许材料上传；未登录时上传者回落为 `system` 以满足 users 外键。

### 工作台第二刀已落地：连贯场景切换 + 实体候选复核

- **新建任务首屏**：点击新建后仍保留最左全局任务栏；右侧是对话式启动页，保留监督目的、任务名称、授权有效期、案件范围，并允许在每案行上挂材料。点“生成分析计划”后启动入口缩放右移进入工作台。
- **左侧收起规则**：只有进入工作台、出现全局栏与任务目录两层左侧结构后，中间顶栏才提供收起全局栏的按钮（等价 Cmd/Ctrl+B）；任务目录是任务的业务对象清单，不提供收起入口。
- **计划进入工作台**：中间先打开 `TASK_SCOPE`，右侧展示步骤；无需再补材料或提示词即可点“执行分析”（确认计划 → 碰撞 → 生成线索）。执行过程在智能体侧以默认折叠的思考块显示，每步带进度条；产物出现在左侧目录与中间区。工作台对话框附件按所选案件走卷宗上传，不再误入会话附件目录。
- **计划前可返回修改**：`SCOPE_DRAFT` 状态允许修改任务名称、监督目的、有效期与案件范围，并为 `TASK_SCOPE` 追加版本；确认后再改必须走 REPLAN。
- **实体候选产物**：抽取/归一步骤通过 `POST /api/tasks/{task_id}/entity-candidates` 写入 `ENTITY_CANDIDATE_SET`。前端展示跨案记录、来源位置、一致依据和差异提示。
- **人工处置闭环**：合并、保持分离、修正、暂缓均要求理由；每次处置为同一 `artifact_id` 追加版本。全部处置后候选集由 `PENDING_REVIEW` 转为 `VALID`；`STALE/INVALID` 候选禁止继续处置。

### 阶段四已落地：统一网关与四角色结构化智能体

阶段四做的是智能体控制面，不是新页面。上下文按角色最小投喂，记忆落在 `model_runs` 与产物版本，检索只读任务范围内的门控脱敏 chunk；BM25 / Embedding 仍留到阶段 6。

- **统一网关** `agents/gateway.py`：所有业务模型调用的唯一入口。注入模型名、`purpose`、`prompt_version`、`input_hash`、审批 ID；写 `model_runs`（用量、耗时、状态、哈希，不写原文）；超时 / 429 最多 3 次指数退避；非法 JSON 不重试、进修复队列；模型名必须在白名单。`GATEWAY_FAKE_MODE` 提供与真实调用同一套 JSON 形状的 Fake。
- **降级**：`DEEPSEEK_EXTERNAL_CALLS_ENABLED=false` 或缺少密钥时进入「仅确定性规则」模式；`GET /api/agent/status` 明示 `degraded`。材料、任务与产物接口仍可用。
- **四角色** `agents/structured_roles.py`：抽取、归一说明、线索表述、输出校核。输入输出均为 Pydantic Schema。抽取对象必须带证据，且 `quote_hash` 能在对应脱敏 chunk 中反向匹配；`confidence` 只用于排序。归一只列异同与核对问题，不给是否同一人的结论。线索表述不得新增事实或引用。校核独立运行，只判定不改写。禁止定论词在输出侧规则复核。
- **任务接入** `tools/tasks.py`：`list_gated_chunks` 按任务案件范围 + 外发门控取最小片段；`run_extraction` 把提及写入 `ENTITY_CANDIDATE_SET` 并关联 `run_id`。相同 `purpose + prompt_version + input_hash` 复用已成功运行。
- **接口**（均在 `app/main.py`）：`GET /api/agent/status|runs|repair-queue`；`POST /api/tasks/{id}/roles/extract|normalize|clue-wording|verify`。

### 阶段五第一刀已落地：确定性碰撞与跨案线索

不依赖 Embedding，本轮不做 Neo4j。目标是在任务范围内产出第一条可回原文核验的跨案线索。

- **规则抽取与标准化** `tools/entities.py`（`EXTRACTOR_VERSION=stage5-rule-v2`）：在本地扫描 `text_raw`（不出网）抽取手机号、银行卡（Luhn）、身份证（校验位）、IMEI、IP；提及表同时保留原文 surface、规范值与脱敏引用。银行卡支持连续写法与空格/横杠等分隔符分组写法，**先去分隔符再做 Luhn**；仅尾号、掩码号入表但不参与强碰撞（`normalized_value` 为空或标记 masked）。OCR 混淆只生成可能等价形式，不覆盖原文。
- **排除名单** `config/rules/exclusions.yaml`：公共客服号、测试数据等不进入碰撞。
- **强标识碰撞**：同一规范值出现在 ≥2 个案件且每案 ≥1 有效 chunk → `PENDING` 候选写入 `ENTITY_CANDIDATE_SET`。系统不提供自动合并。`KEEP_SEPARATE` 按 fingerprint 记忆，同输入不再复现。重跑按 fingerprint 复用 `candidate_id`，不复制待复核记录。复核命令携带 `expected_version`。
- **任务级 ReAct 智能体（主流程）**：`agents/task_agent.py` + `POST /api/tasks/{id}/agent/chat`。DeepSeek 在右侧智能体框内思考并调用任务工具（`get_task_overview` / `confirm_task_plan` / `run_task_collision` / `run_task_timeline` / `generate_task_clues` 等）；SSE 推送思考、工具调用与观察；工具返回的 `artifact_id` 以卡片链接出现，点开后走中间预览（与目录同一 `artifact_id`）。「执行分析」按钮改为向智能体下达自然语言指令，不再由前端硬编码流水线。Fake/外呼关闭时降级为工具直跑，仍在智能体框内展示执行过程。
- **R001–R003**：同卡 / 同手机号 / 同设备跨案，YAML 定义见 `config/rules/rules.yaml`。命中证据模式为 `DIRECT_MATERIAL`。作为**工具内部**确定性能力供智能体调用，不是页面按钮算法。
- **事件事实层**：`tools/entities.py` 的 `EVENT_EXTRACTOR_VERSION=stage5-event-v1` 在本地按句抽取 `TRANSFER` / `CONTACT`，写入 `event_mentions`，并由 `run_task_timeline` 工具生成 `ROLE_TIMELINE`。
- **R004 / R005（已接）**：基于事件层同键跨案，不引入 Neo4j。R004：同一完整账户出现在 ≥2 案的转账事件；R005：同一完整手机号出现在 ≥2 案的联络事件。证据模式为 `RULE_INFERRED`。
- **线索卡**：`generate_clues` 走「规则命中 → 线索表述角色 → 输出校核」；校核不通过不落可见产物。每条线索 ≥2 案件、≥2 chunk；含固定法律边界声明。
- **原文回链**：`GET /api/materials/versions/{id}/chunks/{id}?quote=&quote_hash=` 校验失败返回引用失效，不静默展示旧内容。
- **界面空结果与可滚动**：提及 / 候选 / 线索 / 时间线分区分别说明「扫到提及但无跨案完整强标识」「线索来自 R001–R003」「只有标识没有行为描述时时间线可为 0」等，避免把 0 条当成程序未跑；工作台根布局改为可纵向滚动，长内容不再被页面底部截断。材料页主按钮恢复为「执行分析」（碰撞 → 线索 → 事件时间线），避免只抽时间线导致目录里看不到实体候选/关联线索；`ROLE_TIMELINE` 以可视化时间轴展示（有时间/时间不明分组），不是图谱。
- **接口**：`POST /api/tasks/{id}/collision/run`、`POST /api/tasks/{id}/clues/generate`、`POST /api/tasks/{id}/timeline/run`。工作台可一键碰撞、生成线索、抽取转账/联络事件时间线，并渲染 mentions / 线索卡 / 时间线卡片。
- **金标准对齐（G001）**：演示同卡 R001 时，完整卡须 Luhn 通过。合成号可用 `6228480177334163`（原 `…4160` 校验失败会被丢掉）；材料中可保留空格写法。**A/B 两案都要写同一张通过校验的完整卡**，只改一案或只留尾号/掩码不会出线索。尾号、掩码手机、Luhn 失败卡号会作为可见提及保留，但不进强碰撞。上传时只拆 A/B 案证据，不要整份 Word、不要三表。
- **本轮已核验**：两案同手机号/同卡/同 IMEI 可碰撞；带空格完整卡号去分隔后可与连续写法对上并出 R001；掩码号、仅尾号与排除名单（如 `13800138000`）不生成候选；姓名非强标识不合并；重跑幂等；`KEEP_SEPARATE` 后同 fingerprint 不再以 PENDING 复现；错误 `quote_hash` 返回引用失效；`GATEWAY_FAKE_MODE` 下线索表述与校核可落卡。G001 同卡端到端冒烟通过；两案文本材料可抽出 `TRANSFER` / `CONTACT` 事件并落 `ROLE_TIMELINE`；同账户转账跨案可出 R004、同手机联络跨案可出 R005。删除材料会同步作废目录中的 `MATERIAL_DOC` 并刷新批次。Neo4j 多跳投影仍未做。

### 代码落位：沿用原有结构，不新增分层

阶段三没有新建 `app/api`、`app/services`、`tools/parsing` 之类的分层目录，全部能力回到仓库原有的两个位置：

- `tools/files.py`：文件上传之后的所有处理都在这一个文件里，按注释分段——状态与错误码、SQLite 建表与访问、授权契约、敏感信息脱敏、解析与页级 OCR、稳定分块、`MaterialService` 业务编排、Agent 工具函数。
- `tools/tasks.py`：监督分析任务与产物模型（含 `chat_messages`）；阶段四起负责任务范围 chunk 检索与四角色编排，阶段五接线碰撞、线索、事件时间线与任务工具。
- `tools/entities.py`：实体提及、可逆标准化、强标识碰撞、R001–R005，以及转账/联络事件抽取。
- `config/rules/`、`config/normalization/`：排除名单、规则 YAML、OCR 混淆词典。
- `agents/gateway.py`：统一模型网关；`agents/task_agent.py`：任务级 ReAct。
- `app/main.py`：所有 HTTP 接口（材料、任务/产物、任务智能体 SSE、任务绑定 `/chat/{task_id}`）。
- `app/config.py`：存储目录、`MATERIAL_AUTH_MODE`、上传/OCR/分块、外呼开关、网关与提示词版本。

把持久化、解析、脱敏、门控、业务编排都放进 `tools/files.py`，是因为它们服务同一件事——一份卷宗从落盘到可被安全引用；拆开只会让调用链在多个文件间反复跳转。数据库访问以 `_insert`/`_update`/`_row`/`_rows` 四个通用函数加少量领域函数实现，不再有独立的仓储类和转发层。`model_runs` 与修复队列建在 `agents/gateway.py` 内，不另起仓储层。

`search_lawlibrary.py` / `policy_query.py` 面向本地法规与政策知识库，`files.py` 面向案件电子卷宗，两者业务对象不同，未互相覆盖。

测试样例文件的构造函数放在 `test/conftest.py`，测试模块直接 `from conftest import ...`，因此 `test/` 下不需要 `__init__.py`，也避免与标准库同名的 `test` 包冲突。
