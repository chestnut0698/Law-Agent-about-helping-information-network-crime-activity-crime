# 链证智析

 目前项目名称为：

“链证智析”——面向基层检察院的帮信罪关联案件证据链条挖掘与漏犯漏罪智能监督系统

## 需求

当前需求：处理串联不同案件卷宗里的证据，发现共同点，发掘上下游犯罪链条，辅助发现遗漏线索。或者能够从大量证据，如涉及大量言词证据、鉴定意见、电子数据等多种证据（诈骗罪、强奸罪、故意伤害罪等）中提取事实和证据要素，重在**发挥大语言模型的语义理解能力**。这一部分需求的实现重在流程设计以及工具快速检索能力（RAG）。

## 项目实现

### 已有（会话原型）

当前对话流程仍按步数执行：每一步以大模型返回文字为结束；系统提示词可要求中间步骤输出空语句，直到最后一步生成完整回答。会话附件仍可通过 `/conversations/{conv_id}/upload` 落入 `data/workspace/{conv_id}/`（兼容路径，非正式卷宗入口）。

默认接入 DeepSeek 的 `deepseek-v4-flash`（读取 `DEEPSEEK_API_KEY`）。若本地未配置 DeepSeek、只配置了 `NVIDIA_API_KEY`，则自动走 NVIDIA，方便队友本地使用。NVIDIA 手动探针保留在 `test/test.py`。

### 阶段三已落地：案件材料管线（智能体侧）

- **案件级导入 API**：`POST /api/materials/upload` 支持同一请求多文件、按 `case_id` 归属；格式 PDF / PNG / JPEG / DOCX / TXT。
- **版本链**：`documents` + `document_versions`；替换与 OCR 人工修正均新增版本，不覆盖历史；同案同 SHA-256 进入 `DUPLICATE_PENDING`；删除为逻辑删除并返回影响清单。
- **解析 / OCR / 分块**：PyMuPDF 页级取文；低密度页与图片走页级 OCR（已装 PaddleOCR 则用之，否则 Fallback 引擎便于本地/测试）；chunk 稳定键 `document_version_id + ordinal + sha256`（默认 800/120）。
- **状态与质量**：`PARSED` / `NEEDS_OCR_REVIEW` / `OCR_FAILED` / `FAILED` 等；页级置信度与质量标记可查询。
- **脱敏与外发门控**：本地检出姓名/身份证/银行卡/手机/住址/账号；对照映射隔离存放；Agent 仅能读脱敏 chunk，未脱敏拒绝外发。
- **授权**：仅实现授权检查契约（`auth_check(user_id, case_id, action)`），默认 `deny_all`；本地可用环境变量 `MATERIAL_AUTH_MODE=allow_all` 切换测试桩。**完整登录/RBAC 未实现。**
- **Agent 工具**：`list_case_materials`、`get_material_status`、`locate_low_quality_pages`、`read_material_chunk`、`submit_ocr_correction`。

### 代码落位：沿用原有结构，不新增分层

阶段三没有新建 `app/api`、`app/services`、`tools/parsing` 之类的分层目录，全部能力回到仓库原有的两个位置：

- `tools/files.py`：文件上传之后的所有处理都在这一个文件里，按注释分段——状态与错误码、SQLite 建表与访问、授权契约、敏感信息脱敏、解析与页级 OCR、稳定分块、`MaterialService` 业务编排、Agent 工具函数。
- `app/main.py`：所有 HTTP 接口。原有的会话附件接口（`/conversations/{conv_id}/upload` 等）保持不动，案件材料接口（`/api/materials/...`）追加在同一文件的“案件卷宗上传与处理”一节。
- `app/config.py`：新增的存储目录、上传大小、OCR 阈值、分块参数等配置项。

把持久化、解析、脱敏、门控、业务编排都放进 `tools/files.py`，是因为它们服务同一件事——一份卷宗从落盘到可被安全引用；拆开只会让调用链在多个文件间反复跳转。数据库访问以 `_insert`/`_update`/`_row`/`_rows` 四个通用函数加少量领域函数实现，不再有独立的仓储类和转发层。

`search_lawlibrary.py` / `policy_query.py` 面向本地法规与政策知识库，`files.py` 面向案件电子卷宗，两者业务对象不同，未互相覆盖。

测试样例文件的构造函数放在 `test/conftest.py`，测试模块直接 `from conftest import ...`，因此 `test/` 下不需要 `__init__.py`，也避免与标准库同名的 `test` 包冲突。
