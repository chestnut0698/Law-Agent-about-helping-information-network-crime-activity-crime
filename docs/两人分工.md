# 信证智析 — 两人并行分工

> 依据《信证智析设计方案.md》《智能体搭建实施规划.md》整理。  
> 目标：一人守关键路径保证 P0 可演示，另一人用领域资产与旁路能力换时间；能并行的 Issue 尽量并行。

## 1. 角色定位

| | **甲：平台 / 编排主线** | **乙：领域资产 / 旁路能力** |
|---|---|---|
| 重心 | 案件 → 材料 → 脱敏 → Plan → 事实 → 要素 → 复核 → 缺口 → 增量 → 报告 | 合成案卷、要素/规则数据、量刑引擎、类案检索、OCR 增强、看板与评测 |
| 对应设计功能 | 功能一～五、八～九、十一 | 功能六～七、十，以及知识库/数据准备 |
| 主目录 | `app/`、`services/`、`db/`、`agents/`、`security/` | `data/`、`tools/`、`config/*_rules.yaml`、`legal_rules/`、`similar_cases/` |

**合并约定**

- 合并权在甲（迁移编号、公共 Schema、网关接口）。
- 乙不擅自改主链路表结构；优先以 fixture、纯函数、独立模块交付。
- 一次只认领一个 Issue 或子任务（如 `LA-005-A`），按实施规划验收。
- 模型一律走甲维护的 `agents/gateway.py`；乙只交 Schema 与提示词模板。
- 金额用 Decimal；事实必须绑定可回链原文；遵守项目 Skills。

## 4. 分阶段分工

### 4.1 M0：LA-001～004

| 甲（关键路径） | 乙（可同时开工） |
|---|---|
| LA-001 骨架 / 权限 / 审计 | 合成案卷 `tests/fixtures/synthetic_case/`（规划 §6 全套） |
| LA-002-A PDF/DOCX/TXT、哈希、版本、片段 | 帮信罪要素模板 `data/element_templates/` |
| LA-002-B 可与乙协作；甲负责接入服务与页面 | OCR 工具原型 / RapidOCR 适配（LA-002-B） |
| LA-003 脱敏服务 + 模型网关 stub | `safety_rules.yaml`、越界用例文案 |
| LA-004 输入门控与合规替代 | 脱敏检测规则样本、测试用假证件号等 |

**并行要点**

- 乙从第一天写统一合成案卷；甲在 LA-002 E2E 直接使用。
- LA-002：甲做 A，乙做 B；A/B 都通过才算完成 LA-002。
- 乙可先实现脱敏检测器纯函数，甲在 LA-003 接到 `redaction_service`。

**合流点**：M0 门禁（LA-001—004 全部通过）。

### 4.2 M1：LA-005～011

| 甲 | 乙 |
|---|---|
| LA-005-A Plan Schema / 确认页 | `gap_rules.yaml` / `conflict_rules.yaml` |
| LA-005-B/C 执行器 / 检查点 / 预算 | LLM Schema 草案（事实/评价/实体）+ 提示词模板 |
| LA-006-A/B 事实·评价·实体提取 | 要素库 Schema + 映射规则草稿（供 LA-007） |
| LA-007 要素—事实—证据映射 | 时间轴/关系列表页面骨架（可先无真实数据） |
| LA-008-A/B 人工复核闭环 | **启动 LA-012-A**：量刑规则数据 + 纯函数引擎（不碰主 UI） |
| LA-009 缺口与冲突 | **启动 LA-013-A**：类案导入 + BM25/向量索引 |
| **优先 LA-011** 增量 REPLAN | **并行 LA-010** 时间轴 + 实体关系列表 |

**规划明确的并行**

- LA-009 之后：甲做 LA-011，乙做 LA-010（甲守依赖图，乙做可视化）。
- LA-012 与 LA-013 可在 M1 中后段由乙开工，不必等报告。

**合流点**：M1 门禁（LA-005—011）；乙同时交出可单测的量刑引擎与可检索类案库。

## 5. 日常协作

1. 按《智能体搭建实施规划.md》的 Issue 模板开发与验收；不得跳过前置依赖。
2. 迁移序号只由甲申请；乙需要新表时先交接口草案，再并入甲的迁移。
3. 每日至少合流一次：甲保证主分支可跑；乙以分支/PR 交付 fixtures 与纯函数，不堵主线。
4. 每个 Issue 完成后按规划 §31 记录模板填写依赖检查、验收证据与遗留问题。
