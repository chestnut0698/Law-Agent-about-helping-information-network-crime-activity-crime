# 信证智析智能体搭建实施规划

> 本文是《信证智析_PRD.md》的工程执行版。请严格按 Issue 顺序实施；每次只交付一个 Issue 或其标注的子任务，验收通过后再进入下一个。

## 1. 使用方式

### 1.1 每次调用开发模型时

1. 指定唯一 Issue，例如“实现 LA-005-A”。
2. 要求模型先读取：
  - 本文目标 Issue；
  - `信证智析_PRD.md` 对应章节；
  - 本文列出的项目 Skills。
3. 要求模型检查前置 Issue 的代码、迁移和测试是否已存在。
4. 只允许修改目标 Issue 范围内的文件；必要的公共基础设施随首个使用它的 Issue 一起实现。
5. 实现完成后运行目标 Issue 测试、全量回归、静态检查和迁移检查。
6. 对照验收标准逐条报告“通过/未通过/未执行”，不得只说“已完成”。

### 1.2 Issue 统一完成定义

每个 Issue 必须同时交付：

- 可操作的页面或用户入口；
- 服务层业务逻辑，页面不得直接写数据库；
- SQLAlchemy 模型与 Alembic 增量迁移；
- Pydantic 输入输出契约；
- 服务端权限校验；
- 关键写操作审计；
- 异常和恢复路径；
- 单元测试、集成测试及至少一条合成案卷 E2E；
- 对应文档或配置变更。

模型输出相关 Issue 还必须满足：

- 所有模型调用经统一网关；
- 输出通过 Pydantic Schema；
- 事实必须绑定可反向定位的原文片段；
- 无依据时返回空值和“未发现”；
- 不输出定罪、证明标准、确定刑期等越界结论；
- 记录模型、提示词模板、Token、耗时、费用和结果状态。



### 1.3 推荐调用模板

```text

开始前：
1. 阅读目标 Issue 全文、前置依赖和指定 Skills。
2. 检查前置 Issue 是否真实完成；若缺失，只报告阻塞，不绕过依赖。
3. 列出本次准备修改的文件、迁移、接口和测试。

实现要求：
- 严格遵守目标 Issue 范围和函数契约；
- 页面、服务、持久化、权限、审计、测试形成纵向闭环；
- 不实现后续 Issue；
- 不用 mock 冒充正式能力；外部服务可通过明确的测试适配器替代；
- 金额使用 Decimal；
```

## 2. 开工前冻结的决策

在 LA-001 开始前冻结：

- D1 部署形态：默认“比赛原型，单机运行，SQLite”；
- D2 模型策略：DeepSeek 经服务端网关，仅脱敏确认后调用；
- D3 首版量刑地区：必须选择一个具体省份，未选择时 LA-012 不开工；
- D4 多涉案人员粒度：事实、要素和量刑情景支持按涉案人员维护，同时允许 `subject_id` 为空的案级共享数据；
- D5 确认权限：检察官助理可初审，身份、核心行为、关键金额、量刑情节及关键冲突均由承办检察官最终确认；
- D6 文件边界：默认单文件 500 MB、单案 2,000 页，音视频不支持；
- D7 缺口规则维护人和发布流程；
- D8 类案数据来源、授权和首版规模；
- D9 类案权重：建议结构化 0.6、语义 0.4，必须版本化；
- D10 量刑输出：规范参考区间及调节步骤，不是最终量刑建议；
- D11 数据留存和销毁策略；
- D12 P0 关系视图：先实现关系列表，图形化为增强；
- D13 Streamlit 仅用于原型，服务层不得依赖 Streamlit。

未冻结 D1、D2、D4、D5、D6 时不得开始 LA-001。未冻结 D3、D10 时不得开始 LA-012；未冻结 D8、D9 时不得开始 LA-013。

## 9. LA-002 上传、解析并定位案卷



### 目标

让用户批量上传混合格式材料，看到处理状态，并能从片段回到文档版本和页码。

### 子任务

- LA-002-A：PDF/DOCX/TXT、哈希、版本和片段；
- LA-002-B：图片及扫描 PDF OCR。

A 和 B 都通过后才完成 LA-002。

### 新增文件

- `db/models/{document,document_version,chunk}.py`
- `services/ingest_service.py`
- `tools/parsers/{base,pdf_parser,docx_parser,txt_parser,image_parser}.py`
- `tools/ocr/rapid_ocr.py`
- `schemas/api/document.py`
- `app/pages/04_materials.py`



### 数据迁移

`002_documents_chunks` 创建 `documents`、`document_versions`、`chunks`，片段唯一键为 `(document_version_id, page_no, block_no)`。

### 接口契约

```python
def upload_documents(case_id: UUID, files: list[UploadFile], actor: UserContext) -> list[DocumentUploadResult]: ...
def replace_document(document_id: UUID, file: UploadFile, actor: UserContext) -> DocumentVersionDTO: ...
def retry_parse(document_version_id: UUID, actor: UserContext) -> ParseJobDTO: ...
def get_materials(case_id: UUID, actor: UserContext) -> list[MaterialSummaryDTO]: ...
def get_page_preview(document_version_id: UUID, page_no: int, actor: UserContext) -> PagePreviewDTO: ...
def locate_chunk(chunk_id: UUID, actor: UserContext) -> ChunkLocatorDTO: ...
def parse_file(path: Path, mime_type: str) -> ParseResult: ...
```



### 实施步骤

1. 建立按案件隔离的存储目录和文件大小限制。
2. 上传时计算 SHA-256，检测 MIME，不信任文件扩展名。
3. 相同案件同哈希提示重复，不创建新版本。
4. PDF 优先读取文本层；无文本层时进入 OCR。
5. DOCX、TXT 和图片分别解析。
6. 按页、块、字符区间生成稳定片段和原文哈希。
7. 替换文件创建递增版本及 `supersedes_version_id`。
8. 页面展示处理状态、失败原因、页级预览和片段高亮。
9. 损坏文件单独失败，不回滚其他文件。



### 验收标准

1. 混合格式文件均有文档 ID、版本、哈希和状态。
2. 扫描 PDF 生成带页码和位置的 OCR 片段。
3. 重复文件不创建重复版本。
4. 损坏文件不影响其他文件。
5. 任一片段可定位到文档版本、页码和高亮区域。
6. 替换后旧版本仍可审计查看。

## 11. LA-004 请求安全门控与合规替代



### 目标

在读取完整案卷前识别越界请求，提供可执行的合规替代任务。

### 新增文件

- `config/safety_rules.yaml`
- `db/models/safety_decision.py`
- `schemas/llm/safety_classification.py`
- `services/safety_gate_service.py`
- `agents/safety_agent.py`



### 数据迁移

`004_safety_decisions` 保存请求哈希、分类、原因、替代任务和规则版本。

### 接口契约

```python
def classify_request(text: str, case_metadata: CaseMetadata, actor: UserContext) -> SafetyDecisionDTO: ...
def rule_prefilter(text: str) -> SafetyDecisionDTO | None: ...
```

输出只能是 `ALLOW`、`CLARIFY`、`DENY`。

### 实施步骤

1. 先用确定性规则识别直接定罪、证据充分性、确定刑期等请求。
2. 未命中规则时由安全门控角色分类。
3. 安全角色只接收用户请求和案件元数据，不接收案卷正文。
4. `DENY` 返回原因和“事实—证据整理”等替代任务。
5. `CLARIFY` 生成具体追问并令案件进入等待用户状态。
6. 所有决策记录规则版本和审计。



### 验收标准

1. “判断是否构成帮信罪”被拒绝并提供替代任务。
2. “证据是否确实充分”被拒绝且不读取案卷正文。
3. “整理支付结算金额来源”被允许。
4. 模糊请求进入等待用户并给出明确问题。
5. 决策可按请求、规则和模型版本追溯。
